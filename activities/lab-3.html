Lab Exercise #3: One Prompt, Seven Prompt Engineering Frameworks

I rewrote “Explain subnetting” using RTCFC, COSTAR, RISEN, CRAFT, RACE, TRACE and CRISPE.

Original prompt “Explain subnetting.”Frameworks 7
RTCFCCOSTARRISENCRAFTRACETRACECRISPEComparison
Original promptExplain subnetting.

The task: keep the meaning the same, but rebuild the prompt seven times, once per framework, including every component.

1. RTCFC

Role · Task · Context · Format · Constraint

RTCFC promptRole: You are a Certified Network Engineer and IT instructor. Task: Explain what subnetting is, how it works, and why we use it. Context: I am a beginner learning computer networking fundamentals. Format: Three sections, each with a definition, an analogy, and a use case. Constraint: Keep it beginner-friendly and avoid overly complex binary math.

2. COSTAR

Context · Objective · Style · Tone · Audience · Response

COSTAR promptContext: I am learning IT fundamentals and need to know how IP networks are broken up. Objective: Give a complete but easy-to-understand explanation of subnetting. Style: Informative and professional. Tone: Positive and clear. Audience: A tech-curious learner studying computer networking for the first time. Response: Start with a basic definition, explain what subnet masks do, and give a simple numeric example.

3. RISEN

Role · Instructions · Steps · End goal · Narrowing

RISEN promptRole: Senior Network Architect. Instructions: Explain subnetting, focusing on network IDs, host IDs, and subnet masks. Steps: 1. Explain what an IP address and a subnet mask do together. 2. Explain “borrowing bits.” 3. Show how subnetting limits broadcast domains. End goal: Make sure I understand the difference between local and global routing of network traffic. Narrowing: Stick to the basics of IPv4 subnetting.

4. CRAFT

Context · Role · Action · Format · Target

CRAFT promptContext: Modern IT infrastructure relies heavily on organized local area networks (LANs). Role: Technical writer. Action: Break subnetting down into digestible concepts for a learner. Format: A bulleted list followed by a summary table of CIDR notations. Target: Anyone trying to grasp basic IT networking concepts.

5. RACE

Role · Action · Context · Expectation

RACE promptRole: Cisco Certified Network Associate (CCNA) instructor. Action: Describe subnetting by comparing a flat (non-subnetted) network with a segmented one. Context: Flat networks have performance problems caused by broadcast traffic. Expectation: Help me understand how a subnet mask works as a filter that separates the network part from the host part.

6. TRACE

Task · Request · Action · Context · Example

TRACE promptTask: Explain the concept and mechanics of subnetting. Request: Break down how an IP address is split into network and host portions. Action: Give a step-by-step conceptual walkthrough. Context: IP addresses are finite, and networks need efficient traffic management. Example: Use a standard network like 192.168.1.0/24 to show how it can be divided.

7. CRISPE

Capacity · Role · Insight · Statement · Personality · Experiment

CRISPE promptCapacity: Expert in IP addressing and subnetting architecture. Role: Friendly IT mentor. Insight: Subnetting isn't just math; it's about traffic control, security boundaries, and efficiency. Statement: Explain subnetting through the idea of logical network division. Personality: Patient, precise, and practical. Experiment: Include a real-world exercise or mental model I can use to spot subnetting in daily life, like a home router's guest network.

What I noticed

FrameworkBest for
RTCFCEveryday technical requests where the output format matters
COSTARWriting that has to fit an audience and tone, like announcements
RISENTeaching in a fixed order, step by step
CRAFTDocumentation-style output with a set format
RACEShort, focused prompts with a clear expected outcome
TRACEExplanations anchored on a concrete example
CRISPEMentoring-style answers with a personality and an exercise

Every framework pushed me to add the things “Explain subnetting” was missing: who the answer is for, what form it should take, and what to leave out. The frameworks mostly differ in which of those they make you think about first.
