Assignment #1: Foundations of Conversational AI

AI systems I use, LLMs vs. rule-based chatbots, the conversational AI ecosystem, and what a university should check before deploying an AI assistant.

1. Conversational AI systems I use

The assistant I use most is Gemini. Three real tasks I used it for:

TaskHow it helpedLimitation I ran into
Reformatting a driveWalked me through the steps and suggested fixes when it failed.The real cause was a broken connecting wire. The AI couldn't see that, so some of its suggestions didn't apply.
Making a new scheduleTurned my list of classes and tasks into an organized schedule quickly.I still had to check it against my real commitments.
Troubleshooting a game bugSuggested possible causes and things to try.Some suggestions worked and some didn't.
My rule of thumb

AI is helpful for suggesting what to try, but don't rely on it fully. A problem can have causes it can't see, like a physical fault.

2. Large Language Models vs. rule-based chatbots

Traditional rule-based chatbots are basically giant if-else statements. If the user doesn't type the exact keyword the developer mapped out, the bot breaks or loops.

Large Language Models are different. Instead of hard-coded rules, they use neural networks trained on huge amounts of text, so they can work with the meaning and context of what I ask. They generate a response probabilistically, predicting the next most likely token, one token at a time.

Strengths

Flexibility. When I ask an LLM to troubleshoot Laravel routing or fix a database migration, it keeps the context of my earlier prompts and handles multi-part instructions without breaking.

Limitations and risks

  • Hallucinations: sometimes the answers are simply wrong, even when they sound confident.
  • Bias: answers can be shaped by earlier chats or by how the conversation was framed.
  • Over-reliance: because it sounds sure, it's easy to skip checking the answer.

3. The conversational AI ecosystem

A conversational AI system looks a lot like the full-stack web apps we build, with a reasoning engine in the middle. It takes the whole system working together to give a reliable answer.

1
User and interface

The front end, like the Bootstrap layouts I build, where the user types a prompt.

2
Databases and retrieval

Vector databases find relevant context quickly. Relational databases like MySQL store sessions and authentication rules.

3
LLM

The core engine. It combines my prompt with the retrieved data to generate the response.

4
Evaluation

Logging errors and user feedback behind the scenes so the bot improves over time.

I later built exactly this kind of system in the Kualta chatbot, with safety screening and human handoff added.

4. Before AUF deploys an AI assistant for students

ConsiderationWhy it mattersStrategy
Academic integrityStudents might use it to write whole system modules or essays instead of learning the material.Set the system prompt to act strictly as a tutor: for capstone code it gives hints and points out syntax errors, but doesn't write the whole script.
Data privacyStudents may share grades, financial issues or personal records with the chatbot.Database-level access control so the AI only sees the logged-in student's records, and a private deployment so prompts aren't used to train public models.
Factual reliabilityA wrong lab schedule, prerequisite or tuition deadline causes real problems for students.RAG grounded only in official AUF registrar documents and handbooks. If the answer isn't there, it says “I don't know, please ask your professor.”
AccessibilityNot everyone has a high-end laptop or stable internet.A lightweight web portal, or integration into the existing LMS, so any device can use it.
